# Bug Report: RF-03 - Módulo de Pontuação e Ranking

**Título:** Falha no bloqueio de novos check-ins em intervalo inferior a 24h (Violação do RF-09)
**Data do Teste:** 20/05/2026

---

## 1. Descrição
O sistema não está aplicando a regra de negócio que restringe a frequência de check-ins. Conforme o RF-09, o usuário deve ser impedido de realizar um novo check-in caso o envio anterior tenha ocorrido há menos de 24 horas. No cenário testado, o sistema aceita múltiplos envios (conforme evidenciado pelos prints `image_830880.png` e `image_830b43.png`) sem validar o timestamp da última atividade do usuário.

## 2. Severidade
- [ ] **Crítico:** Trava o sistema ou compromete a segurança.
- [x] **Maior:** Causa erro de lógica na regra de negócio (Bypass de restrição de frequência).
- [ ] **Menor:** Erros visuais ou de interface.

## 3. Passos para Reproduzir
1. Realizar um check-in válido via `POST /api/checkins` (ex: "Primeiro Check-in" às 18:44:30).
2. Aguardar um intervalo inferior a 24 horas (ex: o teste foi realizado no mesmo minuto/hora ou pouco tempo depois).
3. Realizar um segundo check-in via `POST /api/checkins` (ex: "Segundo Check-in" às 18:44:39).
4. Observar que a API processa a requisição e retorna `201 Created` para ambos os registros.

## 4. Resultado Esperado
O sistema deve validar a data/hora do último check-in bem-sucedido do usuário no banco de dados. Se o intervalo for menor que 24 horas, a API deve retornar um erro (como `409 Conflict` ou `403 Forbidden`) com a mensagem: "Você já realizou um check-in nas últimas 24 horas".

## 5. Resultado Atual
A API aceita os múltiplos envios (`201 Created`) independentemente do tempo decorrido, permitindo que o usuário acumule pontos de forma indevida e frequente.

## 6. Ambiente de Teste
* **Dispositivo:** Computador local
* **Ferramenta de API:** Insomnia
* **Servidor:** Docker
